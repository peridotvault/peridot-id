The SDK (`@peridotvault/pid-sdk-js`) wraps the API for browsers. It sends credentials with every
request, so the API's cookies are handled automatically.

## Install

```bash
npm install @peridotvault/pid-sdk-js
```

## Initialize

```ts
import { Peridot } from '@peridotvault/pid-sdk-js';

const peridot = Peridot({
  clientId: 'pidapp_…', // your registered app id
  onUnauthorized: async () => {
    // Access token expired — try to refresh silently before redirecting to login
    const ok = await peridot.auth.refresh();
    if (!ok) {
      const url = await peridot.auth.login(); // Google OAuth URL — navigate to it
      if (url) window.location.assign(url);
    }
  },
});
```

That's the whole config. `clientId` is applied to login, exchange, and fiat calls
automatically. The environment is auto-detected: `NODE_ENV === 'production'` →
production, everything else (unset, `development`, `staging`, `test`, …) →
sandbox. The API origin, popup host, Solana RPC, and program id all resolve from
there — chains come from the API registry, not your config.

- Force an environment for a staging build with `env: 'sandbox'`.
- Self-host / localhost: pass advanced `baseUrl` (and `popupBaseUrl`).
- Server-side only: pass `clientSecret` (used by `auth.exchange`) — **never** in
  browser code.

## Sign in

`auth.login()` resolves the Google OAuth URL — navigate to it. The user signs in and is sent back to
`CLIENT_SUCCESS_URL` with the session cookies already set — or, for a new credential,
to the PID picker (`?claim=1`), where they choose the permanent `<handle>@pid`
(check `auth.pidAvailable(handle)` first; the handle can never be changed, reused,
or reassigned):

```ts
const url = await peridot.auth.login();
if (url) window.location.assign(url);
const { available, pid } = await peridot.auth.pidAvailable("ifal");
// { available: true, pid: "ifal@pid" }
const status = await peridot.auth.claimStatus();
// { pending: true, email, displayName, avatarUrl } when a claim is waiting
const claimed = await peridot.auth.claim("ifal");
// { ok: true, pid: "ifal@pid", pidCode? } — session cookies set
```

## Identity

```ts
const me = await peridot.identity.me();
// { id: "ifal@pid", status: "active", createdAt: "2026-08-03T13:30:00.000Z" }
```

### Level

```ts
const summary = await peridot.level.get('ifal@pid');
// { pid, level: 5, total_xp: 1701, current_level_xp: 1701,
//   next_level_xp: 2819, progress_percentage: 0 }
// — or an ApiError ({ statusCode: 404, … }) for unknown users.
```

Read-only: no XP amounts in, none out. See [Levels & XP](/leveling) for the
badge component, the event-reporting contract, and rate limits.

### Login credentials

```ts
const credentials = await peridot.identity.credentials();
// [{ id: "3f9c...", provider: "google", email: "a@b.com", linkedAt, lastLoginAt }]

await peridot.identity.unlinkCredential(credentials[0].id); // true if unlinked
```

Unlinking the identity's last credential fails (returns `false`) — every identity must
keep at least one way to log in.

## Profile

```ts
const profile = await peridot.profile.me();
// { pid, displayName, avatarUrl, locale, createdAt, updatedAt }

const updated = await peridot.profile.update({
  displayName: 'PeridotPlayer',
  locale: 'en-US',
});
```

The PID (`pid`, e.g. `ifal@pid`) is permanent and immutable — only the mutable
labels above can be updated. There is no endpoint that changes, reuses, or reassigns it.

## Wallet

Each identity owns **one personal wallet** — its chain rows (Solana smart
account + EVM counterfactuals), all derived from the PID. Custody is
**non-custodial**: Peridot never generates, holds, or returns any key
material. The authority is the user's sec256r1 passkey (verified on-chain);
the fee payer is a client-held Ed25519 keypair (fee-SOL only), and sponsored
writes go through the relayer (the server pays, the account reimburses +
protocol fee). Discover live chains with `GET /v1/chains` — never hardcode
them.

```ts
const rows = await peridot.wallet.me();
// [{ id, chainNamespace, chainReference, address, accountType, status, ... }]
// or ApiError { statusCode: 404 } when the PID has no wallet yet

const created = await peridot.wallet.createAccount();
// idempotent ensure — same rows back on repeat calls
```

- Creating again returns the **existing** wallet — a PID can never have more than one.
- The wallet belongs to the PID, not to Google (or any other provider). Unlinking a
  credential leaves it untouched, and logging in from another device does not change it.
- `create` returns the API error object on validation failure (`400`).

### Chain support

| Chain | Status | SDK reads | SDK writes |
|---|---|---|---|
| Solana (devnet + testnet rows, `program` contract) | **stable** | `getBalance`, `tokens`, `tokensEnriched`, `tokensRegistry`, `nfts`, `history`/`activity`, `activation`, `feePolicy` | `topup` (direct deposit), `withdraw`/`quoteWithdraw`, `execute`/`quoteExecute` (relayer-sponsored), `activate`, `rotate` |
| EVM counterfactuals (`eip155` testnets: `10143` monad, `97` bsc-testnet, `421614` arbitrum-sepolia, `84532` base-sepolia; `factory` + `account_implementation` required) | **experimental (testnet-only)** | `evmSmartAccountAddress(chainReference)`, `evmActivation(chainReference)` | EVM batch path (`estimateBatch` / `submitBatch` / `getBatchStatus`, relayer-executed sequential — not EIP-4337) |
| Stellar (`stellar-testnet` row; `factory` contract lands at deploy) | **planned** — no `wallet.*` methods yet; only `packages/stellar` scope/network helpers | — | — |

### Balances, history, and what is NOT the wallet

```ts
const lamports = await peridot.wallet.getBalance(); // SOL, on-chain RPC read
const spl = await peridot.wallet.tokens();           // SPL balances + ATA addresses
const list = await peridot.wallet.tokensEnriched();  // balances joined with the curated registry
const nfts = await peridot.wallet.nfts();            // heuristic SPL 0-decimal x1 inventory
const txs = await peridot.wallet.history(30);       // on-chain signatures parsed + merged into the local cache
const one = await peridot.wallet.activity(txs[0]?.id); // cache read only — no API round-trip
```

- **On-chain vs internal ledger vs gateway.** `history`/`activity` read
  Solana RPC and merge into a local cache (`LocalHistoryStore`; cache
  returned on RPC failure) — they are NOT the server ledger.
  `submitTransaction({ intentId, txHash })` records an executed tx against a
  pending intent (`POST /v1/wallet/transactions/submit`). The IDR balance,
  statements, and sends live on the **internal fiat ledger**
  (`peridot.fiat.*`, see [Fiat & payments](/fiat)) — money in via the DOKU
  gateway, never on-chain. XP lives on its own ledger (see
  [Levels & XP](/leveling)).
- Amounts are base-unit decimal strings (lamports/wei/raw units) — never
  floats in fee paths. Fee quotes carry `networkFee`, `platformFee`
  (`serviceFee` is the same EVM value under another name), `totalFee`,
  `maxTotalFee`, `quoteId`/`quotedAt`/`expiresAt`; re-quote past expiry.
- `waitForConfirmation` / `getTransactionStatus` report `confirmed` /
  `failed` / `pending` — treat `pending` as unconfirmed (reorg/finality:
  poll, never assume inclusion).

### Passkey authorities

`peridot.passkey` manages the secp256r1 signing authorities on the wallet —
Google OAuth proves identity, a passkey authorizes it:

```ts
const authorities = await peridot.passkey.list();
const created = await peridot.passkey.register(); // first credential registers freely
await peridot.passkey.revoke(id);
```

### Batched execution (experimental)

`POST /v1/wallet/execute/batch/*` (quote → submit → optional flush, cancel while
queued) is **experimental** and has no `peridot.wallet` wrapper yet — call it
through the raw client or the standalone `estimateBatch(api, …)` /
`submitBatch(api, …)` / `getBatchStatus(api, …)` / `cancelQueuedBatch(api, …)`
helpers. Quote IDs bind the exact op set; a changed op set
rejects with `400 QUOTE_MISMATCH` (re-estimate). Single withdraw/execute quotes
go stale instead: `410` (re-quote).

## Money (fiat)

`peridot.fiat` covers top-up, balance, statement, and sends on the internal IDR
ledger. Full guide: [Fiat & payments](/fiat).

```ts
const bal = await peridot.fiat.balance();          // { balanceIdr, source: 'fiat-ledger', ... }
const view = await peridot.fiat.ledger();          // statement rows
const deposit = await peridot.fiat.checkoutDeposit('100000'); // → { paymentUrl, grossIdr, feeIdr, netIdr }
await peridot.fiat.syncTransaction(deposit.id);    // corroborate payment → credits the ledger
await peridot.fiat.transferViaPopup({ amountIdr: '100000', beneficiaryPid: 'live2dev@pid' });
```

- `checkoutDeposit`, `transferViaPopup`, and `transferConfirm` are trust-critical:
  in popup mode they run on the PeridotID origin (see [Popup flow](#popup-flow-third-party-origins)).
- Fiat methods **throw** `Error` on failure (not the `T | ApiError` union that reads return).
- Pass the initiating app's `clientId` as the second argument to apply that app's
  own fee — it stacks on the global 0.1% (min Rp100, no cap) and credits the app.

## Apps, fees & raw calls

`PeridotClient` also exposes `get` / `post` / `patch` / `put` / `delete` for
endpoints without a dedicated wrapper — app management, per-app fees, and machine
auth use these:

```ts
await peridot.get('/v1/apps');
await peridot.patch(`/v1/apps/${id}`, { allowedOrigins: ['https://mygame.dev'] });
await peridot.put(`/v1/apps/${id}/fees/topup`, {
  percentBps: 200, minIdr: '0', maxIdr: '10000', enabled: true,
});
```

See [Apps & workspace](/apps) for the machine token and the full fee model.

## Log out

```ts
await peridot.auth.logout();
```

## Refreshing

Usually you never call `refresh()` directly — the `onUnauthorized` callback does it. If
you need to force a refresh:

```ts
const ok = await peridot.auth.refresh(); // true if a new session was issued
```

## Errors

Methods return the API error object instead of throwing for failed requests:

```ts
const result = await peridot.profile.me();
if ('statusCode' in result && result.statusCode === 401) {
  // handle unauthenticated
}
```

See [Errors](/errors) for the full error contract.
